# WHL workspace - กติกาสำหรับ Claude

ไฟล์นี้มาจาก plugin `whl-data` (skill `whl-workspace`) ทุกคนในทีมใช้โครงเดียวกัน - แก้เพิ่มได้ แต่อย่าลบกติกาด้านล่าง

## โครงโฟลเดอร์ (เปิด Claude Code ที่โฟลเดอร์นี้เสมอ)
```
projects/<ลูกค้า>-<งาน>/      เช่น brand-a-osa, brand-b-sales, brand-c-sampling
  01_input/    ไฟล์ที่ได้รับ - เก็บตามที่ได้รับ ไม่แก้
  02_data/     ข้อมูลดิบที่ดึงมา (สคริปต์เขียนให้) - ห้ามแก้มือ
  03_output/   ไฟล์ส่งงาน
  scripts/     สคริปต์ / โค้ด Apps Script ของ project
  NOTES.md     ข้อมูลอ้างอิงของ project (อ่านก่อนเริ่มงานทุกครั้ง)
templates/     แม่แบบรายงานที่ใช้ร่วมกัน
_scratch/      ไฟล์ชั่วคราว ลบได้ทุกสัปดาห์ - ห้ามส่งไฟล์จากที่นี่ให้ลูกค้า
```
- งานใหม่ที่ยังไม่มีโฟลเดอร์: ถามชื่อ `<ลูกค้า>-<งาน>` แล้วสร้างด้วย skill `whl-workspace` (คำสั่ง `new`) ก่อนเริ่ม
- ผู้ใช้แนบ/ส่ง path ไฟล์ที่อยู่นอก workspace (เช่น Downloads): ถามว่าเป็นของ project ไหน (หรือเสนอ project ที่คุยอยู่แล้วให้ยืนยัน)
  แล้วคัดลอกเข้า `01_input/` ด้วย skill `whl-workspace` (คำสั่ง `add`) ก่อนทำงาน - ทำงานกับไฟล์ในนั้น ไม่แก้ต้นฉบับ
- รูป/ข้อความที่วางในแชทไม่มีไฟล์บนเครื่อง - ถ้าต้องเก็บ ให้ผู้ใช้บันทึกเป็นไฟล์ก่อน
- ไม่วางไฟล์ไว้ที่ root ของ workspace / ไม่สร้างโฟลเดอร์นอกโครงนี้
- ดึง CloudViu ลง project: ใส่ `--into <ลูกค้า>-<งาน>` ในคำสั่ง cloudviu.py (ไม่ใส่ = ลง `_scratch/`)
- เปิด project CloudViu ครั้งแรก: รัน `profile` (cloudviu-connector) ใส่ `--into <ลูกค้า>-<งาน>` แล้วสรุปลง NOTES.md
  ข้อ ❓ ใน profile ต้องถามทีมก่อนใช้ตัวเลขนั้น / ถ้าผลดึงข้อมูลขึ้น ⚠️ ต้องบอกผู้ใช้ก่อนทำรายงาน
- ข้อมูลอ้างอิงที่เจอระหว่างทำงาน (เลขโปรเจกต์ CloudViu, job, campaign, ความหมายของคำตอบ, ลิงก์ชีตที่เกี่ยวข้อง) ให้บันทึกใน `NOTES.md` ของ project

## ตั้งชื่อไฟล์
`<ลูกค้า>_<เนื้อหา>_<YYYY-MM-DD>[_<YYYY-MM-DD>].<นามสกุล>` เช่น `brand-a_osa_2026-11-01_2026-11-24.xlsx`
- วันที่แบบ ปี-เดือน-วัน เสมอ / ไม่มีช่องว่าง / แก้รอบใหม่ใช้ `_v2` ไม่ใช้คำว่า final

## ความปลอดภัย (นโยบายองค์กร)
1. ห้ามใส่รหัสผ่าน token API key ในโค้ดหรือไฟล์ - ใช้ Credential Manager / Script Properties / env var และเตือนผู้ใช้ทุกครั้งที่เกี่ยวกับ credential
2. ห้ามรับรหัสผ่านในแชท ห้ามพิมพ์รหัสหรือกดอนุญาตสิทธิ์ (OAuth) แทนผู้ใช้
3. ข้อมูลลูกค้าและพนักงาน (ชื่อ เบอร์ อีเมล ที่อยู่ รูป พิกัด): ใช้เท่าที่จำเป็น ตัด/มาสก์ก่อนส่งออก
   ห้ามส่งไปบริการหรือ API ภายนอกที่องค์กรไม่ได้อนุมัติ ห้ามแชร์ไฟล์แบบ "Anyone with the link"
4. งานที่เขียน/ลบข้อมูลจริง (CloudViu, ชีตที่ใช้งานอยู่, ส่งอีเมล, deploy) ต้องทดสอบกับสำเนาหรือโปรเจกต์ทดสอบก่อน
   แสดงสิ่งที่จะเปลี่ยน แล้วรอผู้ใช้ยืนยัน และแนะนำให้คนที่มีพื้นฐานเทคนิคตรวจก่อนใช้จริง
5. ก่อนเชื่อม MCP / API ภายนอกตัวใหม่ ถามผู้ใช้ว่าตรวจความน่าเชื่อถือแล้วหรือยัง และแนะนำให้ปรึกษาทีม IT
6. ให้สิทธิ์เท่าที่จำเป็น (least privilege) ไม่แนะนำสิทธิ์ admin ถ้าไม่มีเหตุผล
7. งานที่แตะ credential สิทธิ์ หรือการเชื่อมระบบภายนอก ปิดท้ายด้วย "ควรให้ทีม IT ตรวจสอบก่อนใช้งานจริง"
