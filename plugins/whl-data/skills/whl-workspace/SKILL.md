# WHL workspace มาตรฐาน

ทุกคนใช้โครงเดียวกัน คนอื่นเปิดงานต่อได้ทันที และ Claude รู้ว่าไฟล์อยู่ไหน
สคริปต์: `python ${CLAUDE_SKILL_DIR}/scripts/workspace.py <คำสั่ง>` (ไม่ลบ ไม่เขียนทับไฟล์ที่มีอยู่)

```
~/WHL/                          <- เปิด Claude Code ที่นี่เสมอ (มีไฟล์ .whl-workspace)
├─ CLAUDE.md                    <- กติกาสำหรับ Claude (โครงโฟลเดอร์ + ความปลอดภัย)
├─ projects/<ลูกค้า>-<งาน>/       เช่น brand-a-osa, brand-b-sales, brand-c-sampling
│   ├─ 01_input/   ไฟล์ที่ได้รับ - ไม่แก้
│   ├─ 02_data/    ข้อมูลดิบที่ดึงมา - ห้ามแก้มือ (CloudViu ใส่ --into <ชื่อ>)
│   ├─ 03_output/  ไฟล์ส่งงาน
│   ├─ scripts/    สคริปต์ / Apps Script
│   └─ NOTES.md    ข้อมูลอ้างอิงของงาน
├─ templates/      แม่แบบใช้ร่วมกัน
└─ _scratch/       ไฟล์ชั่วคราว (CloudViu ที่ไม่ใส่ --into ลงที่นี่)
```

## Claude ทำอะไรเมื่อไร
| สถานการณ์ | ทำ |
|---|---|
| ผู้ใช้ยังไม่มี workspace | ขออนุญาตแล้ว `init` (ค่าเริ่มต้น `~/WHL`) แล้วบอกให้ปิด/เปิด Claude Code ที่โฟลเดอร์นั้น |
| เริ่มงาน / ลูกค้าใหม่ | ถามชื่อ `<ลูกค้า>-<งาน>` 1 คำถาม แล้ว `new <ชื่อ>` แล้วช่วยกรอก NOTES.md |
| เริ่มทำงานใน project ที่มีอยู่ | อ่าน `projects/<ชื่อ>/NOTES.md` ก่อน |
| ดึงข้อมูล CloudViu | ใส่ `--into <ชื่อ>` -> ลง `02_data/` |
| สร้างรายงาน | อ่านจาก `02_data/` เขียนไปที่ `03_output/` ตั้งชื่อตามมาตรฐาน |
| เจอข้อมูลอ้างอิงใหม่ (เลขโปรเจกต์ job ความหมายคำตอบ ลิงก์ชีต) | บันทึกใน NOTES.md |
| ผู้ใช้ถามว่าเก็บถูกไหม / ก่อนปิดงาน | `check` แล้วแก้ตามที่บอก |

## คำสั่ง
| คำสั่ง | ทำอะไร |
|---|---|
| `init [--root <path>]` | สร้าง workspace (ปฏิเสธถ้าอยู่ใน OneDrive / Drive ที่ซิงก์) |
| `new <ลูกค้า>-<งาน>` | สร้างโฟลเดอร์ project + NOTES.md (มีแล้ว = เติมส่วนที่ขาด) |
| `check` | ตรวจโครง ชื่อ project ไฟล์ที่วางผิดที่ |
| `list` | รายชื่อ project |

## ตั้งชื่อไฟล์
`<ลูกค้า>_<เนื้อหา>_<YYYY-MM-DD>[_<YYYY-MM-DD>].<นามสกุล>` เช่น `brand-a_osa_2026-11-01_2026-11-24.xlsx`
วันที่แบบ ปี-เดือน-วัน / ไม่มีช่องว่าง / รอบแก้ใช้ `_v2` ไม่ใช้ final

## กติกา
- ห้ามเก็บ workspace ใน OneDrive / Google Drive ที่ซิงก์ หรือโฟลเดอร์แชร์ (ข้อมูลดิบมีข้อมูลลูกค้าและพนักงาน)
- ห้ามย้าย/ลบไฟล์ของผู้ใช้เอง - บอกว่าควรย้ายไปไหน แล้วให้ผู้ใช้ยืนยันก่อน
- NOTES.md ห้ามมีรหัสผ่าน ชื่อหรือเบอร์พนักงาน
